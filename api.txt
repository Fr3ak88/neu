Data to storelogix

Login and Access-Token

Each REST communication is secured with Basic Authentication according to RFC 2617, the

access data are individually defined for each participant.



Each REST request requires an access token, which is obtained by logging in to the rest server

with the respective access data.

Each request runs in its own transaction, so the tokens cannot be used in parallel in several

requests.

If a token is nevertheless used in parallel, all subsequent requests wait in the order of the calls

until the respective previous transaction has been completed.

Request a new token

GET

https://api.storelogix.de:<Port>/REST/Order/Login?username=<UserID>&password=

<Password>

or

https://api.storelogix.de:<Port>/REST/Article/Login?username=<UserID>&password=

<Password>

<UserID> and <Password> are assigned separately per connection.

If for security reasons the login data must not be included in the URL, this can be passed in the

http header under "SessionAuth" as <UserID>;<Password>:

SessionAuth: IFC-TEST;hretg87#z

If the login was successful, a json structure with the new access token is returned:

1 {
2 "ErrorCode": 0,
3 "Message": "",
4 "AccessToken": "E588B8F1-6B3A-438E-A2C7-977678DA6711",
5 "TokenType": "AccessToken",
6 "ExpiresIn": 360
7 }

If the login fails, "ErrorCode" <> 0 and an error message is returned in "Message".

The returned access token is valid for up to "ExpiresIn" value and can be used for all further

REST requests.

Feedback from storelogix

The respective order or purchase order numbers and their item numbers are always referenced.

The feedbacks are transmitted to a given REST URL with POST.

If a transmission was not successful, this is repeated several times at intervals of 1 minute. To

ensure synchronization, failing transmissions are not deferred.

storelogix → Goods receipt completed

(can come multiple times for different items)

storelogix → Loading completed

storelogix → Unplanned changes in stock

Pull Feedback Messages

The REST interface can be used to retrieve feedback from storelogix that has not yet been

processed.

Either individually or several at once.

The oldest, not yet processed confirmations are always transferred first.

There is a separate endpoint for each feedback type.

REST-Call

GET

1 https://api.storelogix.de:<Port>/REST/get_response/<FeedbackType>?Receive

FeedbackType: Type of Feedback, for example DeliveryOrderResponse or 

GoodsReceiptResponse

ReceiverName: Recipient of the feedback, if nothing is specified, all feedback for the current

communication partner is returned.

ResponseCount: Maximum number of feedback messages to be output.

If not specified, only one response is output at a time.
